# Парсер расшифровок

Код: `backend/app/parser/`. Версия: `PARSER_VERSION` в `transcript.py`. Парсер детерминированный, LLM не использует.

## Формат приложения тьютора (по первому занятию 08.11.2026)

- Самая новая реплика вверху, первая — внизу.
- Реплика AI заканчивается строкой «Скрыть текст».
- Реплика ученика начинается с метки `MM:SS`.
- Метка — **длительность голосового сообщения**, а не время: значения не монотонны, их сумма (≈34 мин) больше длительности занятия из заголовка («16 мин»). Для порядка не используются.
- «Показать текст» — свёрнутая реплика AI, её текста в копии нет.
- Служебные строки: «Сменить роль», «16 мин», «В любой момент можно сменить роль», «— кнопка вверху экрана.», «Грамматические ошибки», «Просто говорите – не бойтесь ошибиться».
- Строка на русском у края документа — заголовок сценария («собеседование в СНГ компанию на дата-аналитика middle уровня»).

Список служебных строк — `markers.py`, расширяется без изменения логики.

## Алгоритм

1. **Разбиение на элементы**: абзацы текста, метки времени, «Скрыть текст», «Показать текст». Пустые и служебные строки — разрывы между абзацами (количество запоминается).
2. **Заголовки**: абзацы с долей кириллицы ≥ 60% до первого и после последнего маркера.
3. **Роли** (в порядке документа):
   - абзац сразу после метки — ученик (длительность берётся из метки);
   - абзац прямо перед «Скрыть текст» — AI;
   - если между ними несколько абзацев — граница по самому большому разрыву; при равенстве флаг `split_ambiguous`;
   - «Показать текст» — реплика AI без текста (`collapsed`), следующему ответу ставится `question_missing`;
   - префиксы `Tutor:` / `Me:` / `Я:` / `Ученик:` и т. п. — явная роль;
   - без меток, но с маркерами AI — роль ученика по чередованию (`role_inferred`, требует подтверждения);
   - иначе `unknown`, сохранить можно только после ручного выбора роли.
4. **Порядок** — сумма голосов сигналов: `score = Σ vote × weight × strength`, где vote = +1 (прямой) или −1 (обратный).

| Сигнал | Вес | Как считается |
| --- | --- | --- |
| `qa_coherence` | 2.0 | Сходство (по основам слов без стоп-слов) вопроса AI со следующим ответом ученика и обратной связи AI с предыдущим ответом; сравниваются оба варианта порядка. strength = min(1, 3 × \|разница\| / сумма) |
| `greeting_edge` | 1.5 | Приветствие («Hello», «nice to meet you», «I'll be your interviewer») только у одного края |
| `closing_edge` | 1.5 | Завершение («end this dialogue», «summary of our…», «goodbye») только у одного края |
| `timestamps` | 1.0 | Только если метки строго монотонны (похожи на время); иначе голос 0 |
| `user_preference` | 0.5 | Последний подтверждённый порядок пользователя |

Уверенность: `confidence = min(1, |score| / (Σ весов сигналов с голосом, кроме предпочтения + 0.5))`. Пороги: ≥ 0.6 высокая, ≥ 0.3 средняя, иначе низкая.

Подтверждение пользователя обязательно, если: уверенность не высокая; порядок выбран вручную и расходится с определённым; содержательные сигналы противоречат сохранённому предпочтению; есть роли по чередованию или `unknown`; роли изменены вручную.

## Что парсер не делает

- Не исправляет текст, не удаляет повторы и запинки («I... I», «they, they») — это задача анализа, и они не считаются ошибками.
- Не сортирует по меткам времени.
- Не исправляет ошибки распознавания («Yanbudexmetrica») — это будет статус `recognition_uncertainty` на этапе анализа.

## Проверено

- Синтетические тесты: обратный и прямой порядок, без меток, с префиксами, без маркеров, CRLF, свёрнутая реплика, конфликт с предпочтением (`backend/tests/test_parser.py`).
- Реальное занятие 08.11.2026 (локально, не в репозитории): 17 реплик ученика, 18 AI (1 свёрнута), порядок обратный, уверенность 0.70 без предпочтения, 0 реплик с неопределённой ролью.
