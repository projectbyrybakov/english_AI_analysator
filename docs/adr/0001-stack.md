# ADR 0001. Стек: FastAPI + Next.js + PostgreSQL

Дата: 2026-11-08. Статус: принято.

## Контекст

ТЗ рекомендует Next.js + TypeScript и разрешает отдельный FastAPI с обоснованием. В сервисе много обработки текста (леммы, части речи, лексическое разнообразие) и расчёта метрик. Пользователь — аналитик данных, работает с Python и pandas. Разработка ведётся с AI-ассистентом, сопровождение — один человек.

## Решение

- Backend: Python 3.12+, FastAPI, SQLAlchemy 2, Alembic, Pydantic.
- Frontend: Next.js (App Router), TypeScript, без UI-фреймворков.
- База: PostgreSQL 16.
- Запуск: Docker Compose; CI в GitHub Actions.

## Почему

- Лингвистические метрики (лемматизация, части речи) в Python заметно надёжнее, чем в JavaScript (spaCy и аналоги).
- Метрики и проверки удобно писать и перепроверять на Python; пользователь может сам читать этот код.
- Pydantic даёт валидацию JSON от LLM по схеме.
- Next.js — по рекомендации ТЗ, хорошая адаптивность и SSR при необходимости.

## Цена решения

Два приложения вместо одного: два Dockerfile, два набора зависимостей. Это не микросервисы — один backend, одна база. Альтернатива «всё на TypeScript» проще в деплое, но слабее в NLP.
